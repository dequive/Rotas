# Phase 13.5: Workshop Operations Expansion — Context

**Gathered:** 2026-06-18
**Status:** Ready for planning
**Source:** PRD Express Path (user specification)

<domain>
## Phase Boundary

This phase expands the existing `workshop` module backend (18 endpoints, 10 models, all production-ready) with five capability pillars:

1. **Workshop Staff** — assign tasks to mechanics, track time, compute labor cost automatically
2. **Tool Calibration History** — full calibration log per tool, auto-alerts for critical tools near expiry
3. **Serialized Spare Parts** — per-serial-number tracking for tires, batteries, extinguishers; install/scrapped lifecycle linked to vehicle
4. **Unified Vehicle History** — cursor-paginated chronological timeline aggregating all intervention types
5. **UI Expansion** — 4-tab `/manutencao` page + `/viaturas/[id]/historico` timeline page

**What this phase does NOT touch:**
- Existing 18 endpoints in `workshop/router.py` — no removals, no breaking changes
- Existing models structure — only ADD columns; no DROP or ALTER TYPE
- Existing WorkOrder state machine (draft → approved → in_progress → quality_check → closed)
- Existing tool checkout logic (`ToolCheckout` model and checkout/return flow)
- Existing spare parts movement (weighted average cost calculation in `SparePartMovement`)
- Existing maintenance plan/schedule evaluator (ARQ cron)

</domain>

<decisions>
## Implementation Decisions

All decisions below are locked — they come directly from the product owner's specification.

### Pillar 1 — Workshop Staff

- `WorkOrderTask` gets 3 new nullable columns: `assigned_to UUID FK → users.id`, `estimated_minutes INT`, `actual_minutes INT`
- `WorkOrder` gets 1 new column: `labor_cost Numeric(14,2) DEFAULT 0` — separate from `actual_cost` (parts cost)
- New table `workshop_staff_rates`: `id UUID PK`, `tenant_id UUID FK`, `user_id UUID FK → users.id`, `hourly_rate Numeric(10,2)`, `effective_from DATE`, `created_at TIMESTAMPTZ` — includes RLS + GRANT in same migration
- Labor cost accumulation: on task completion, read the mechanic's **active** rate (highest `effective_from <= NOW()`), compute `actual_minutes / 60.0 * hourly_rate`, add to `work_orders.labor_cost` — never recalculate in batch
- New endpoint: `PATCH /workshop/work-orders/{wo_id}/tasks/{task_id}` — assigns mechanic + sets estimate (existing `complete_task` endpoint is untouched; `actual_minutes` is set there)
- `GET /workshop/kpis` response extended with: `total_labor_hours`, `total_labor_cost`, `work_orders_by_mechanic` (list of `{user_id, name, work_order_count, total_hours}`)
- Role `mechanic` added to existing roles enum — write access to workshop module only; no billing, contracts, tenant settings access

### Pillar 2 — Tool Calibration History

- `WorkshopTool` gets 6 new columns: `category VARCHAR(40)`, `location VARCHAR(120)`, `serial_number VARCHAR(80)`, `purchase_date DATE`, `purchase_cost Numeric(10,2)`, `calibration_interval_days INT`
- New table `tool_calibrations`: `id UUID PK`, `tenant_id UUID FK`, `tool_id UUID FK → workshop_tools.id`, `calibrated_by UUID`, `calibrated_at TIMESTAMPTZ`, `next_due_at TIMESTAMPTZ`, `notes TEXT`, `created_at TIMESTAMPTZ` — includes RLS + GRANT in same migration
- `record_tool_calibration(tool_id, calibrated_by, notes, db)` service function: creates `ToolCalibration` row + updates `workshop_tools.calibration_due_at` to `next_due_at`
- Auto-alert logic: when `calibration_interval_days` is set and `calibration_due_at < NOW() + INTERVAL '30 days'` and `is_critical=True` → call `ensure_exception()` (existing alert mechanism)
- New endpoints: `POST /workshop/tools/{id}/calibrations`, `GET /workshop/tools/{id}/calibration-history`
- Updated endpoint: `PATCH /workshop/tools/{id}` — allows updating `status`, `location`, `calibration_interval_days`, `category`

### Pillar 3 — Serialized Spare Parts

- `SparePartInventory` gets 5 new columns: `category VARCHAR(40)` (values: `filtro/pneu/bateria/correia/outro`), `shelf_location VARCHAR(80)`, `supplier_name VARCHAR(160)`, `lead_time_days INT`, `reorder_quantity INT`
- New table `spare_part_serial_items`: `id UUID PK`, `tenant_id UUID FK`, `part_id UUID FK → spare_parts_inventory.id`, `serial_number VARCHAR(120)`, `status VARCHAR(30)` (values: `in_stock/installed/scrapped`), `vehicle_id UUID nullable FK → vehicles.id`, `installed_at TIMESTAMPTZ nullable`, `scrapped_at TIMESTAMPTZ nullable`, `notes TEXT`, `created_at TIMESTAMPTZ` — includes RLS + GRANT in same migration
- Unique constraint: `(tenant_id, serial_number)` — serial numbers are globally unique per tenant
- Install flow: `install_serial_item(serial_id, vehicle_id, db)` → sets `status=installed`, `vehicle_id`, `installed_at=NOW()` + creates `SparePartMovement(direction=out, movement_type=serial_install)` in same transaction
- Low stock query: `WHERE current_quantity <= minimum_quantity AND status='active'`
- New endpoints: `POST /workshop/spare-parts/{id}/serials`, `POST /workshop/spare-parts/serials/{serial_id}/install`, `GET /workshop/vehicles/{vehicle_id}/installed-parts`, `GET /workshop/spare-parts/low-stock`

### Pillar 4 — Unified Vehicle History

- Endpoint: `GET /api/v1/vehicles/{vehicle_id}/history` in `vehicles/router.py`
- Query params: `from` (ISO date), `to` (ISO date), `types` (comma-separated: `maintenance,work_order,fuel,checklist,incident,schedule`), `cursor` (base64 opaque), `limit` (default 50, max 200)
- Implementation: `get_vehicle_history(vehicle_id, tenant_id, ...)` in `vehicles/service.py`
- Uses UNION ALL with 6 independent sub-queries (one per entity type), each selecting: `event_type`, `event_date`, `title`, `description`, `reference_id`, `odometer_reading`
- Final ORDER BY `event_date DESC, id DESC` applied outside the UNION
- Cursor: base64-encoded `"{event_date_iso}|{uuid}"` pair — decode on next request for keyset pagination
- Response shape: `{"events": [...], "next_cursor": str|null, "total_count": int}`
- Entities aggregated: `maintenance_requests`, `work_orders`, `vehicle_refuels` (join `fuel_logs`), `checklists`, `trip_incidents`, `maintenance_schedule`

### Pillar 5 — UI Expansion

- `apps/manager/app/manutencao/page.tsx`: wrap existing content in `<Tabs defaultValue="work-orders">` from shadcn/ui; 4 tab triggers: "Ordens de Trabalho" / "Peças e Stock" / "Ferramentas" / "Planos Preventivos"
- New file `apps/manager/app/manutencao/components/PartsInventoryTable.tsx`: columns SKU / Nome / Stock Actual / Stock Mínimo / Custo Médio / Categoria / Prateleira; badge amber dot ("stock baixo") when `current_quantity <= minimum_quantity`
- New file `apps/manager/app/manutencao/components/ToolsTable.tsx`: columns Código / Nome / Status / Calibração Próxima / Localização; badge red dot ("calibração vence") when `calibration_due_at < now + 30d`
- New page `apps/manager/app/viaturas/[id]/historico/page.tsx`: vertical timeline, one card per event, icon per `event_type`, ISO date, title, description, link to referenced entity
- New API functions in `apps/manager/app/lib/workshop-api.ts`: `loadSparePartsInventory()`, `loadTools()`, `loadLowStockParts()`, `loadToolCalibrationHistory(toolId)`, `loadVehicleHistory(vehicleId, params)`
- Follow DESIGN.md: Manrope for all text, IBM Plex Mono for IDs/dates/numeric values, amber `#f59e0b` as accent, dot badges with `::before` circle, no decorative gradients

### Migration Rules (v2.0 mandatory)

Every new table with `tenant_id` MUST have in the SAME Alembic migration file:
```sql
ALTER TABLE {table} ENABLE ROW LEVEL SECURITY;
ALTER TABLE {table} FORCE ROW LEVEL SECURITY;
CREATE POLICY rls_{table} ON {table}
    USING (tenant_id::text = current_setting('app.tenant_id', true));
GRANT SELECT, INSERT, UPDATE, DELETE ON {table} TO rotas_app;
```
This applies to: `workshop_staff_rates`, `tool_calibrations`, `spare_part_serial_items`

### Testing

- Every new service function has a corresponding pytest test
- Tests use the existing async test pattern (`pytest-asyncio`, `asyncio_mode="auto"`, `httpx` ASGI client)
- Cross-tenant isolation verified: a `workshop_staff_rate` created under tenant A is not visible when querying as tenant B
- New test files: `test_workshop_staff_rates.py`, `test_tool_calibrations.py`, `test_spare_part_serials.py`, `test_vehicle_history.py`

### Claude's Discretion

- Exact Alembic migration filename (follow existing convention: `{hex}_{description}.py`)
- Whether to run calibration auto-alerts inside the existing ARQ cron or trigger inline on tool update (recommend: inline on tool update + existing cron for scheduled checks)
- TypeScript interface names for new API response types
- Exact shadcn/ui component variants for tab styling (follow existing usage in codebase)

### workshop_staff_rates — active rate query

```python
# Get active rate for mechanic at a point in time
stmt = (
    select(WorkshopStaffRate)
    .where(
        WorkshopStaffRate.tenant_id == tenant_id,
        WorkshopStaffRate.user_id == user_id,
        WorkshopStaffRate.effective_from <= func.now(),
    )
    .order_by(WorkshopStaffRate.effective_from.desc())
    .limit(1)
)
```

### Vehicle History UNION shape

Each sub-query must SELECT these exact aliases:
```sql
SELECT
    'maintenance_request' AS event_type,
    requested_at AS event_date,
    request_type AS title,
    description,
    id AS reference_id,
    odometer_reading
FROM maintenance_requests
WHERE tenant_id = :tenant_id AND vehicle_id = :vehicle_id
```
