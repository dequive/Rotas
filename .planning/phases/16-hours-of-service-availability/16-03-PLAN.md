async def get_ct_cached(db, tenant_id, redis=None, ...):

    key = f"ct:kpis:{tenant_id}"

**GET /availability/drivers implementation:**

1. Compute cache key: `av:drivers:{tenant_id}`
2. Try Redis GET — if hit, parse JSON and apply status filter + pagination in Python, return
3. If miss: query `select(Driver).where(Driver.tenant_id == principal.tenant_id, Driver.status == "active")` — fetch all active drivers (no limit — we cache the full fleet)
4. For each driver, call `await availability_service.driver_availability_summary(db, principal.tenant_id, driver.id)`
5. Enrich each summary with `driver_name: driver.full_name`
6. Compute `hos_status`: from `summary.get("hos", {}).get("status", "ok")` — default "ok" if HOS data not yet computed (Plan 02 may not be merged yet)
7. Cache the full list as JSON with TTL 30s + stampede NX lock (5s)
8. Apply `status` filter in Python:
   - `"available"` → `item["available"] == True`
   - `"hos_warning"` → `item.get("hos_status") == "warning"`
   - `"hos_violation"` → any blocker with code "driver_hos_violation" in `item["blockers"]`
   - `"unavailable"` → `item["available"] == False`
   - `None` → no filter
9. Apply `offset` and `limit` to filtered list
10. Return `{total: int, items: list, offset: int, limit: int}`

**GET /availability/vehicles implementation:**

Same pattern with key `av:vehicles:{tenant_id}`:
1. Query `select(Vehicle).where(Vehicle.tenant_id == principal.tenant_id)` — all vehicles (no status filter on query — include inactive for full picture)
2. For each vehicle, call `await availability_service.vehicle_availability_summary(db, principal.tenant_id, vehicle.id)`
3. Enrich with `plate_number: vehicle.plate_number`
4. Compute `computed_status`:
   - If any blocker code is `"vehicle_workshop_blocked"` → `"in_maintenance"`
   - Elif any blocker code is `"vehicle_assignment_conflict"` → `"in_trip"`
   - Elif `not summary["available"]` → `"unavailable"`
   - Else → `"available"`
5. Cache with TTL 30s
6. Apply status filter:
   - `"available"` → `computed_status == "available"`
   - `"in_trip"` → `computed_status == "in_trip"`
   - `"in_maintenance"` → `computed_status == "in_maintenance"`
   - `"unavailable"` → `computed_status == "unavailable"`
7. Apply pagination, return same shape

**Error handling:** If `vehicle_availability_summary` or `driver_availability_summary` raises `ApiError` for a single entity (e.g., entity deleted mid-request), catch and skip that entity with a log warning — do not fail the entire list.

**Redis unavailable:** If `redis is None`, skip cache logic entirely, compute from DB directly. Same as control_tower pattern.

Use `json.dumps(items, default=str)` for serialization (handles UUID and datetime types).
