# Phase 04.1 Plan 05: Control Tower and Fleet Compliance Board Migration Summary

Migrated ControlTowerOverview and FleetComplianceBoard from legacy local components and CSS class patterns to shared design system primitives, eliminating the critical dynamic `border-l-${tone}` Tailwind class bug and four duplicate local `Worklist` implementations.

## Tasks Completed

| Task | Name | Commit | Files |

| 1 | Migrate ControlTowerOverview to shared primitives | 1163505 | apps/manager/app/components/ControlTowerOverview.tsx |
| 2 | Migrate FleetComplianceBoard to shared primitives | d367897 | apps/manager/app/components/FleetComplianceBoard.tsx |

## What Was Built

### ControlTowerOverview.tsx

**Replaced local components:**
- `TowerMetric` (6 instances) → `KpiCard` with semantic prop (info/warning/success/error)
- `Worklist` (6 instances across 2 sections) → `WorkQueue` (direct API mapping — same item shape)
- `.operational-heading` div → `PageHeader` with eyebrow, title, description, meta props
- `.data-source` div → `DataSourceBadge` with source and message props
- `.bg-[#edf2f7] border-line` → `bg-surface-2 border-border` tokens on fleet facts bar
- `.compliance-grid` → `grid grid-cols-1 md:grid-cols-2 gap-3 mt-3` Tailwind

**Kept local:**
- `FleetFact` component — compact fact strip with no shared equivalent

**Critical bug fixed:** The `border-l-${tone}` dynamic class concatenation in `TowerMetric` caused Tailwind to purge those classes in production builds. Replaced with `KpiCard` which uses `semantic` prop and a static color lookup — no dynamic concatenation.

### FleetComplianceBoard.tsx

**Replaced patterns:**
- `.domain-section` / `.domain-heading` / `.eyebrow` / `.module-state` → `PageHeader` with `eyebrow`, `title`, `description`, `actions` props
- `.bg-panel border border-line` on `ComplianceColumn` → `bg-surface border border-border rounded-lg overflow-hidden`
- `.queue-icon orange` on column icon → `bg-warning-bg text-warning` token classes
- `.empty-state` paragraph → inline empty `div` with `py-8 text-center` and `text-[12px] text-muted`
- Inline `text-orange` expiry span → `StatusBadge` with `expired`/`expiring_soon` status keys
- `.border-line` → `border-border` in item dividers and form inputs
- `text-red` → `text-error` on error messages
- `hover:bg-soft` → `hover:bg-surface-2` on renew button

**Preserved:** All business logic — useState form state, useRouter, fetch calls with Idempotency-Key headers, renew handler with error handling.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] TypeScript null type error in DataSourceBadge message prop**
- **Found during:** Task 2 verification (first build run)
- **Issue:** `result.message` is typed as `string | null | undefined` but `DataSourceBadge.message` expects `string | undefined`. Dynamic ternary passed `null` when source is not "api".
- **Fix:** Added `?? undefined` coercion: `result.source !== "api" ? (result.message ?? undefined) : undefined`
- **Files modified:** `apps/manager/app/components/ControlTowerOverview.tsx`
- **Commit:** d367897

### Infrastructure Note (not a deviation)

The `npm run build` final step fails with `EINVAL: invalid argument, readlink` on Windows/OneDrive — this is a pre-existing environment issue with Next.js symlinks and OneDrive file system. TypeScript compilation (`tsc --noEmit`) exits cleanly with zero errors. The TypeScript phase of `npm run build` also passes ("Linting and checking validity of types..." succeeds in build output) before hitting the symlink error. This is unrelated to the code changes in this plan.

None — both components are fully wired to real API data from `ControlTowerLoadResult`.
