## Summary

The manager app has a functioning dashboard with all domain modules present, but the styling layer is a dual-system mess. There are two parallel systems: legacy CSS classes (`.queue-icon`, `.eyebrow`, `.badge`, `.panel`, `.worklist`, `.tool-btn`, etc.) defined in `globals.css`, and shadcn/ui components installed at `components/ui/` but only used in `analytics/page.tsx`. The remaining ~19 components use the legacy classes exclusively.

The design token system in DESIGN.md is fully specified and authoritative. However, the CSS variable declarations are fragmented: `globals.css` has three separate `:root` blocks — one correct (the DESIGN.md-aligned HSL block), one legacy hex-variable block, and one shadcn `@layer base` block that uses oklch values that are COMPLETELY WRONG for ROTAS branding (default shadcn zinc theme with no customization). The oklch block is overriding the HSL block because `@layer base` applies after `:root` outside a layer, meaning shadcn components currently render with default zinc colors, not amber.

The shadcn `button.tsx` currently maps `bg-primary` to whatever `--primary` is — the HSL block sets it to amber correctly, but the oklch block at the bottom of `@layer base` then overrides it to a dark blue-gray. This is a critical bug that must be fixed in Wave 0 before any other work proceeds.

**Primary recommendation:** Fix the CSS variable conflict first (remove the oklch `@layer base` block, keep only the correctly-tuned HSL block), then build the component library on top of the working token system before migrating any existing component.

### Pattern 4: KpiCard

```tsx
// app/components/ui/KpiCard.tsx
// Source: DESIGN.md KPI Cards spec
import { cn } from '@/lib/utils'

interface KpiCardProps {
  label: string
  value: string | number
  trend?: { direction: 'up' | 'down'; label: string }
  icon?: React.ReactNode
  semantic?: 'default' | 'amber' | 'error' | 'success'
  className?: string
}

export function KpiCard({ label, value, trend, icon, semantic = 'default', className }: KpiCardProps) {
  const valueColor = {
    default: 'text-ink',
    amber: 'text-amber-dark',
    error: 'text-error',
    success: 'text-success',
  }[semantic]

  return (
    <div className={cn('bg-surface border border-border rounded-lg p-4 shadow-sm', className)}>
      <div className="flex items-center justify-between mb-3">
        <span className="text-[11px] font-semibold uppercase tracking-wide text-muted">{label}</span>
        {icon && <span className="text-muted">{icon}</span>}
      </div>
      <div className={cn('font-mono text-[26px] font-medium leading-none', valueColor)}>
        {value}
      </div>
      {trend && (
        <div className={cn('mt-1.5 text-[11px] flex items-center gap-1',
          trend.direction === 'up' ? 'text-success' : 'text-error'
        )}>
          {trend.direction === 'up' ? '↑' : '↓'}
          <span>{trend.label}</span>
        </div>
      )}
    </div>
  )
}
```

**Critical:** The value uses `font-mono` (IBM Plex Mono) — this is required by DESIGN.md for all KPI values. The current implementations use Manrope with `text-[22px]` or `text-[26px]` bold, which is wrong.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Modal/Dialog | Custom backdrop + focus trap | shadcn Dialog (Radix) | Focus trap, scroll lock, a11y, keyboard escape |
| Dropdown menus | Custom click-outside + z-index | shadcn DropdownMenu (Radix) | Collision detection, keyboard nav, pointer events |
| Select inputs | `<select>` HTML element | shadcn Select (Radix) | Custom styling, keyboard nav, searchable |
| Tooltips | Custom hover div | shadcn Tooltip (Radix) | Positioning, delay, portal, a11y |
| Color-coded dot badges | CSS `::before` pseudo-element | Inline `<span>` (see Pattern 3) | React doesn't support `::before` in JSX directly; inline span is simpler and testable |
| Variant props | `if/else` className strings | CVA (already installed) | Type-safe variant props, composable |
| Class merging | Manual string concatenation | `cn()` from `lib/utils` | Handles Tailwind class conflicts |
| Slide-over panels | Custom right-panel CSS | shadcn Sheet | Accessible slide animation, focus management |
| Tab navigation | Custom active state logic | shadcn Tabs | ARIA role=tablist, keyboard arrows |
| Font-mono numbers | Custom CSS class `.mono` | `font-mono` Tailwind utility | Maps to IBM Plex Mono via tailwind.config fontFamily |

**Key insight:** The current codebase hand-rolls dialogs (`.modal-backdrop` + `.modal` CSS classes). All four modal components (`VehicleFormModal`, `DriverFormModal`, `ContractFormModal`, `TripFormModal`) use this pattern. These must be migrated to shadcn Dialog to get proper a11y and keyboard escape behavior.

## Common Pitfalls

### Pitfall 1: oklch Override Bug (ACTIVE — must fix first)

**What goes wrong:** All shadcn components render with default zinc colors because the `@layer base { :root }` block with oklch values sits AFTER the manually-tuned HSL block and overrides it.
**Why it happens:** shadcn CLI appended its default theme to `globals.css` when components were installed, and nobody noticed because the legacy CSS classes were still working.
**How to avoid:** Remove the entire `@layer base { :root { ... oklch ... } }` block. Keep only the single tuned `:root` inside `@layer base` as described in Pattern 2.
**Warning signs:** `bg-primary` renders as dark slate-gray instead of amber.

### Pitfall 2: `font-mono` Utility Not Resolving to IBM Plex Mono

**What goes wrong:** `font-mono` resolves to the default Tailwind mono stack (Courier, etc.) not IBM Plex Mono.
**Why it happens:** `fontFamily.mono` is not configured in `tailwind.config.ts`.
**How to avoid:** Add `fontFamily: { mono: ['IBM Plex Mono', 'monospace'] }` to `theme.extend` in `tailwind.config.ts`.
**Warning signs:** KPI values render in Courier New instead of IBM Plex Mono.

### Pitfall 3: Dynamic Tailwind Class Names Don't Work

**What goes wrong:** Patterns like `border-l-${tone}` (seen in `ControlTowerOverview.tsx` line 213) generate class names not present in the CSS bundle.
**Why it happens:** Tailwind scans source files for complete class names. Dynamic concatenation (`border-l-${tone}`) doesn't match any file scan, so the class is never included in the build.
**How to avoid:** Use a lookup object:
```tsx
const toneBorder = { blue: 'border-l-blue', red: 'border-l-error', orange: 'border-l-warning', ... }
// Then: className={toneBorder[tone]}
```
**Warning signs:** Colored left borders don't appear in production build (works in dev because of JIT full rebuild on every request).

### Pitfall 4: shadcn Dialog Does Not Work with Server Components

**What goes wrong:** Importing `Dialog` from shadcn in a Server Component causes a build error (uses `useState` internally).
**Why it happens:** All Radix primitives are client-side (use hooks). shadcn Dialog is client-side.
**How to avoid:** Modal components (`VehicleFormModal`, etc.) must have `"use client"` at the top. They already do — keep this.
**Warning signs:** Build error: "You're importing a component that needs `useState`. It only works in a Client Component."

### Pitfall 5: Forgetting IBM Plex Mono on Plate Numbers and IDs

**What goes wrong:** Vehicle plates (`MQ-42-AB`) and trip IDs render in Manrope.
**Why it happens:** Easy to miss — plates are often just `<span>{plate}</span>`.
**How to avoid:** Apply `font-mono text-[12px]` to all cells containing plate numbers, trip IDs, document references, and monetary values. Create a `<MonoCell>` utility component.
**Warning signs:** Plate numbers look the same size and weight as driver names in table rows.

### Pitfall 6: Sidebar Section Headers Breaking the Grid Gap

**What goes wrong:** Section headers disrupt the `grid gap-1.5` layout of the nav, causing inconsistent spacing.
**Why it happens:** Section headers have different size than nav items but are in the same grid.
**How to avoid:** Use `flex flex-col` for the nav instead of grid. The section header labels become flex children with `pt-5` (first section) or `pt-4` (subsequent) plus `pb-1` for visual separation.

### Pitfall 7: tailwind-merge Conflicts with Legacy CSS Classes

**What goes wrong:** `cn('bg-panel', someConditionalTailwindClass)` — `bg-panel` is a Tailwind shortcut referencing a CSS variable, but tailwind-merge doesn't know it's a background color. If `someConditionalTailwindClass` includes `bg-surface`, both classes appear in the output.
**Why it happens:** tailwind-merge uses static analysis of class names — it doesn't resolve CSS variable aliases.
**How to avoid:** When migrating, use full Tailwind classes (`bg-white` / `bg-[var(--surface)]` / `bg-surface`) not legacy aliases. During migration, avoid mixing legacy classes with new Tailwind utilities in the same `cn()` call.

### Pitfall 8: Modal Scroll on Mobile

**What goes wrong:** Modals with long content don't scroll on mobile devices — content is clipped.
**Why it happens:** Current modal CSS: `max-height: 92vh; overflow-y: auto` — this works but shadcn Dialog may override it.
**How to avoid:** Use `DialogContent` with `className="max-h-[90vh] overflow-y-auto"` explicitly.

## UX Patterns for Premium B2B Dashboards (Confidence: MEDIUM)

Based on analysis of the existing codebase and DESIGN.md direction. Not verified against external sources since the design system is fully specified.

### Loading States

**Pattern:** Skeleton rows matching exact height of real content. Already used in analytics page — apply everywhere.
```tsx
// For table rows during load:
{loading ? (
  Array.from({ length: 5 }).map((_, i) => (
    <TableRow key={i}>
      <TableCell><Skeleton className="h-4 w-[180px]" /></TableCell>
      <TableCell><Skeleton className="h-4 w-[120px]" /></TableCell>
    </TableRow>
  ))
) : rows.map(row => <RealRow key={row.id} row={row} />)}
```

### Empty States

**Pattern:** Centered message with context-specific explanation. Never just show a blank area.
```tsx
<div className="py-16 text-center border-t border-border">
  <p className="text-[14px] font-semibold text-ink mb-1">Sem viagens a cobrar</p>
  <p className="text-[13px] text-muted">Quando viagens forem entregues e validadas, aparecerão aqui.</p>
</div>
```

### Sticky Table Actions Column

Already present in legacy CSS (`.table th:last-child` sticky). Preserve this — it's correct UX for wide tables.

### Data Freshness Indicators

The `.data-source` component (`.data-source.api` / `.data-source.fallback`) is a useful pattern that should become a shared component. Shows whether data comes from live API or fallback. Keep this pattern.

### IBM Plex Mono for Monetary Values

Every currency display in table cells and KPI cards must use `font-mono`. Current codebase uses `font-extrabold text-ink` (Manrope) for KPI values, which is wrong per DESIGN.md. This is the single most impactful visual change.
