## Component Inventory

New components required for Phase 4 (both in `apps/manager/app/components/`):

### DriverScorecardPanel

Layout: Extends the `.grid` pattern (4-column) or `.transport-kpis` (6-column) — use `.transport-kpis` with 4 columns for the 4 metric breakdown, plus one summary card showing the composite score.

Structure:
```
DriverScorecardPanel
  ├── Summary card (composite score 0–100, tier badge, rolling window label)
  ├── Metric card: Delivery proof rate (%)
  ├── Metric card: Sync discipline (batches/trip)
  ├── Metric card: Distance (km in period)
  └── Metric card: Stop efficiency (avg min/km, inverted)
```

CSS classes to reuse: `.transport-kpis`, `.transport-kpi`, `.badge`, `.badge.green/.orange/.red`

Each metric card uses `.transport-kpi` pattern:
- Top: lucide icon (color `--blue`)
- Middle: label span (12px `--muted`)
- Bottom: value strong (21px `--ink`)

### MaintenanceImminentPanel

Layout: Extends `.worklist` / `.fleet-compliance-panel` pattern — single-column panel with header and item list.

Structure:
```
MaintenanceImminentPanel
  ├── Panel header (icon + title + count badge)
  └── Item list
        └── ImminentItem (vehicle plate + plan name + trigger type + due value)
```

CSS classes to reuse: `.fleet-compliance-panel`, `.fleet-compliance-list`, `.fleet-compliance-item`, `.history-marker`, `.badge`

Item layout mirrors `.history-event` — two-column grid: marker column + content column.

## Interaction Contracts

### Scorecard: Driver Selection
- Default view on Motoristas page: shows aggregate fleet scorecard (all drivers, rolling 30d)
- Click any driver row or select from dropdown: panel updates to show that driver's individual scorecard
- State change is client-side only (no page navigation) — React state in parent page component
- Loading state: skeleton shimmer using `--line` background on metric card bodies (no spinner)

### Scorecard: Insufficient Data State
- Trigger: driver has fewer than 3 completed trips in the rolling 30-day window
- Display: composite score replaced with "Dados insuficientes" badge (`.badge` no color modifier, text `--muted`)
- Individual metrics still shown with available data (partial is acceptable)
- Tooltip/note below score: "Mínimo 3 viagens em 30 dias para score válido"

### Maintenance Imminent Panel: Empty State
- Trigger: no vehicles with maintenance due in next 30 days or within 500km threshold
- Display: uses `.empty-state` class with `.worklist-item` container
- Copy: "Sem manutenções iminentes" (heading) + "Todas as viaturas estão dentro dos limites de intervenção." (body)
- No action button in this state

### Maintenance Imminent Panel: Interaction
- Items are read-only — display only, no inline actions
- Each item links to the vehicle's workshop view (future phase): for now, no link, just display
- Panel refreshes on page load (server-side rendered data via Next.js server component pattern)

## States Required Per Component

### DriverScorecardPanel

| State | Trigger | Visual Treatment |
|-------|---------|-----------------|
| Loading | API fetch in progress | Metric card bodies show `--line` background blocks (height of value text) |
| Data — score ≥ 80 | Computed score | Green badge, metric values populated |
| Data — score 60–79 | Computed score | Orange badge, metric values populated |
| Data — score < 60 | Computed score | Red badge, metric values populated |

## Accessibility

- All icon-only buttons must have `title` attribute (matches existing pattern in SidebarLayout)
- Score badges must include aria-label with full text: `aria-label="Score: 74 — Amarelo"` (not just the badge color name)
- Maintenance panel list items must use semantic `<ul>/<li>` or `role="list"` with `role="listitem"`
- Color alone must not be the only differentiator — score tier badge includes text label ("Verde", "Amarelo", "Vermelho") alongside color
- Minimum touch target for interactive elements: 38px height (existing `.tool-btn`, `.primary-btn` convention)
