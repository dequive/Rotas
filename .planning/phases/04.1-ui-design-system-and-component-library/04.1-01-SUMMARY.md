## What Was Done

### Task 1: globals.css

The original file had two conflicting CSS contexts:
- Lines 1-65: a custom `:root` block with proper amber HSL tokens (`--primary: 38 92% 50%`)
- Lines 2149-2217: a second `@layer base { :root { ... } }` block with oklch values that **overrode** all the custom tokens, making `--primary` resolve to dark zinc (`oklch(0.21 0.006 285.885)`)

The fix: wrap the correct `:root` block in `@layer base`, add `@apply border-border` and `@apply bg-background text-foreground` to `* {}` and `body {}` inside the layer, add all DESIGN.md semantic tokens (success, warning, error, info, surfaces, transitions, sidebar tokens), and remove both trailing conflicting `@layer base` blocks entirely.

**Result:** Zero oklch values. One `@layer base` block. `--primary: 38 92% 50%` is the single authoritative amber value.

### Task 2: tailwind.config.ts

Extended the existing Tailwind config with:
- `fontFamily.mono: ['IBM Plex Mono', 'monospace']` — `font-mono` Tailwind utility now resolves to IBM Plex Mono
- `fontFamily.sans: ['Manrope', 'system-ui', 'sans-serif']` — explicit Manrope mapping
- Full DESIGN.md semantic token palette: amber, blue (with light/dark variants), success, warning, error, info (with bg variants)
- Surface tokens: bg, surface, surface-2, border-strong
- Text tokens: ink-2, placeholder
- Sidebar tokens: sidebar-bg, sidebar-hover, sidebar-active, sidebar-text, sidebar-text-active, sidebar-section
- All existing shadcn HSL token mappings preserved

**Key decision:** `muted` Tailwind color maps to `var(--muted-color)` (the `#64748b` text gray), not `var(--muted)` (the shadcn HSL token `213 27% 96%` used for background surfaces). This prevents `text-muted` from rendering as a pale blue-gray background color.

### Task 3: shadcn components

Ran `npx shadcn@latest add tooltip dropdown-menu tabs popover sheet alert --yes` from `apps/manager/`. All 6 component files generated with new-york style per components.json. Build passes.
