# Phase 13.5 Plan 02: Workshop ORM Models, Schemas, and Mechanic Role — Summary

**One-liner:** Extended workshop ORM with 3 new model classes + 15 new columns, added 11 Pydantic schemas, introduced MECHANIC role scoped to WORKSHOP_WRITE_ROLES only.

---

## New ORM Classes Added

| Class | Table | Purpose |
|---|---|---|
| `WorkshopStaffRate` | `workshop_staff_rates` | Per-mechanic hourly rate with effective date; supports active-rate lookup for labor cost calculation |
| `ToolCalibration` | `tool_calibrations` | Full calibration log per tool with `calibrated_at` / `next_due_at` timestamps |
| `SparePartSerialItem` | `spare_part_serial_items` | Per-serial-number lifecycle for tires, batteries, extinguishers; install/scrapped lifecycle linked to vehicle |

---

## Existing Models Extended

| Model | New Columns |
|---|---|
| `WorkOrderTask` | `assigned_to UUID FK→users.id (ondelete=SET NULL, named)`, `estimated_minutes INT`, `actual_minutes INT` |
| `WorkOrder` | `labor_cost Numeric(14,2) DEFAULT 0` |
| `WorkshopTool` | `category VARCHAR(40)`, `location VARCHAR(120)`, `serial_number VARCHAR(80)`, `purchase_date DATE`, `purchase_cost Numeric(10,2)`, `calibration_interval_days INT` |
| `SparePartInventory` | `category VARCHAR(40)`, `shelf_location VARCHAR(80)`, `supplier_name VARCHAR(160)`, `lead_time_days INT`, `reorder_quantity INT` |

## New Pydantic Schemas Added

**Workshop Staff Rates:**
- `WorkshopStaffRateCreate` — user_id, hourly_rate (Decimal gt=0), effective_from (date)
- `WorkshopStaffRateOut` — with `ConfigDict(from_attributes=True)`

**Task Assignment:**
- `TaskAssignRequest` — assigned_to UUID, estimated_minutes optional

**Tool Calibration:**
- `ToolCalibrationCreate` — calibrated_by, calibrated_at, next_due_at, notes
- `ToolCalibrationOut` — with `ConfigDict(from_attributes=True)`
- `ToolUpdateRequest` — status, location, calibration_interval_days, category (all optional)

**Serialized Spare Parts:**
- `SerialItemCreate` — serial_number (1-120 chars), notes optional
- `SerialItemInstallRequest` — vehicle_id
- `SerialItemOut` — with `ConfigDict(from_attributes=True)`

**Vehicle History:**
- `VehicleHistoryEvent` — event_type, event_date, title, description, reference_id, odometer_reading
- `VehicleHistoryResponse` — events list, next_cursor, total_count

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] ORM assigned_to FK did not match Wave 1 migration named constraint**
- **Found during:** Task 4 — alembic check revealed `Detected removed foreign key (assigned_to)(id) on table work_order_tasks`
- **Issue:** Plan specified `ForeignKey("users.id")` (unnamed), but Wave 1 migration created `fk_work_order_tasks_assigned_to_users` with `ondelete='SET NULL'`. Alembic autogenerate detected the mismatch.
- **Fix:** Changed `assigned_to` column to `ForeignKey("users.id", ondelete="SET NULL", name="fk_work_order_tasks_assigned_to_users")`
- **Files modified:** `backend/app/modules/workshop/models.py`
- **Commit:** 68fcf95

**2. [Rule 1 - Bug] SparePartSerialItem used simple index=True instead of named composite indexes**
- **Found during:** Task 4 — alembic check revealed removal of `ix_spare_part_serial_items_tenant_part` and `ix_spare_part_serial_items_tenant_vehicle` and addition of simple `ix_spare_part_serial_items_part_id` / `ix_spare_part_serial_items_tenant_id`
- **Issue:** Plan specified `index=True` on individual columns, but Wave 1 migration created named composite indexes (including a partial index with `postgresql_where`).
- **Fix:** Added `__table_args__` with explicit `Index("ix_spare_part_serial_items_tenant_part", "tenant_id", "part_id")` and `Index("ix_spare_part_serial_items_tenant_vehicle", "tenant_id", "vehicle_id", postgresql_where=text("vehicle_id IS NOT NULL"))`. Removed `index=True` from `tenant_id` and `part_id` columns.
- **Files modified:** `backend/app/modules/workshop/models.py`
- **Commit:** 68fcf95
