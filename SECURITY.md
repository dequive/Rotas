# Security Policy

## Supported versions

Only the release-candidate branch and the latest production release receive
security fixes. No working-tree, local image or uncommitted build is a
supported release.

## Reporting a vulnerability

Do not open a public issue containing exploit details, credentials, tenant
data or personal data. Use GitHub private vulnerability reporting for this
repository. If that channel is unavailable, contact the repository owner
privately and provide the affected SHA, impact, reproduction steps and any
suggested mitigation.

Reports are acknowledged as soon as an accountable security owner is
available. Critical and high findings block release until fixed and retested,
or until a time-bounded exception satisfies the versioned release policy.

## Disclosure

Coordinate disclosure with the repository owner. Never test against tenant or
production data without written authorization and an agreed scope.
