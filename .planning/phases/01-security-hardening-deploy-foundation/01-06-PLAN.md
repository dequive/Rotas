<tasks>

<task type="checkpoint:human-action">
  <name>Task 1: Deploy backend to Railway and set required environment variables</name>
  <what-built>
    railway.toml at repo root with preDeployCommand (alembic upgrade head) and startCommand
    (uvicorn backend.app.main:app --host 0.0.0.0 --port $PORT). backend/__init__.py created.
    .env.example documents all required env vars.
  </what-built>
  <how-to-verify>
    Deploy steps:

    1. Go to railway.app and create a new project (or use existing).
    2. Connect your GitHub repo to Railway.
    3. Railway will detect railway.toml automatically.

    Set these environment variables in Railway project settings → Variables:
    - `ENVIRONMENT` = `production`
    - `JWT_SECRET_KEY` = (generate with: python -c "import secrets; print(secrets.token_urlsafe(48))")
    - `DATABASE_URL` = `postgresql+asyncpg://` + Railway PostgreSQL connection string
      IMPORTANT: Railway's PostgreSQL add-on gives you `postgresql://user:pass@host/db`.
      You MUST prefix it with `postgresql+asyncpg://` — just replace `postgresql://` with
      `postgresql+asyncpg://`. Do NOT use the Railway-provided URL as-is.
    - `CORS_ORIGINS` = `["https://YOUR-VERCEL-APP.vercel.app"]` (fill in after Vercel deploy)

    Trigger a deploy. In the Railway deploy logs, confirm:
    - The preDeployCommand output shows Alembic migration lines ("Running upgrade...")
    - The app starts and logs show "Application startup complete"

    After deploy, visit: `https://YOUR-RAILWAY-URL.up.railway.app/health`
    Expected response: `{"status": "ok"}`

    Also visit: `https://YOUR-RAILWAY-URL.up.railway.app/version`
    Expected: `{"version": "0.1.0", "environment": "production"}`
  </how-to-verify>
  <resume-signal>
    Type the Railway backend URL (e.g., "https://rotas-backend-production.up.railway.app") once:
    1. /health returns {"status": "ok"}
    2. /version returns {"environment": "production"}
    3. Railway deploy logs show Alembic migration output
  </resume-signal>
</task>

<task type="checkpoint:human-action">
  <name>Task 2: Deploy manager to Vercel and configure CORS</name>
  <what-built>
    apps/manager/vercel.json with framework: nextjs. Both package.json files have
    engines.node = "20.x". The manager frontend is ready to deploy from apps/manager/.
  </what-built>
  <how-to-verify>
    Deploy steps:

    1. Go to vercel.com and import your GitHub repo.
    2. In the Vercel project setup, set **Root Directory** to `apps/manager`.
       This is critical — without this, Vercel will try to build from the repo root
       and fail ("next: command not found").
    3. Framework will be detected as Next.js automatically from vercel.json.

    Set these environment variables in Vercel project settings → Environment Variables:
    - `ROTAS_API_BASE_URL` = `https://YOUR-RAILWAY-URL.up.railway.app` (from Task 1)
      Note: Do NOT use NEXT_PUBLIC_ prefix — this is a server-only env var.

    Trigger a deploy.

    After deploy:
    1. Visit the Vercel URL (e.g., https://rotas-manager.vercel.app)
    2. Should redirect to /login
    3. Attempt login with a valid user account

    Then update Railway CORS_ORIGINS with the Vercel URL:
    - `CORS_ORIGINS` = `["https://rotas-manager.vercel.app"]`
    - Trigger a new Railway redeploy to apply the CORS_ORIGINS change.

    Verify CORS by opening browser DevTools → Network tab → attempt login → confirm
    the backend request succeeds (not blocked by CORS policy).
  </how-to-verify>
  <resume-signal>
    Type "deployed" once:
    1. Vercel URL is accessible (redirects to /login)
    2. Login succeeds with a real user account
    3. CORS_ORIGINS is updated in Railway with the Vercel URL
    4. Backend requests from Vercel are not blocked by CORS policy
  </resume-signal>
</task>
