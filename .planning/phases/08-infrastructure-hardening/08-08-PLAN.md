  <how-to-verify>
**INFRA-01 — Sentry (requires SENTRY_DSN_* env vars configured in your test environment):**

1. Start the backend with SENTRY_DSN_BACKEND set to your Sentry project DSN
2. Trigger a test error:
   ```bash
   curl -X POST http://localhost:8000/api/v1/test-error  # or any endpoint that throws
   ```
   Alternative: temporarily raise an exception in any endpoint and call it
3. Check your Sentry dashboard — the error should appear within 60 seconds
4. Verify the event has NO fields named: driver_name, cargo_description, phone, nuit, email, plate_number, receiver_name, receiver_contact
5. Optional (if DSN configured): repeat for manager app (Next.js) and driver PWA

If you do NOT have Sentry configured yet, skip this section — verify only that:
- `grep "sentry_sdk.init" backend/app/main.py` returns 1 match inside lifespan
- `grep "SENTRY_DSN_BACKEND" backend/app/main.py` returns 1 match (the guard)
- `cat apps/manager/instrumentation.ts | grep SENTRY_DSN_MANAGER` returns 1 match
- `grep "sentryVitePlugin\|SENTRY" apps/driver/vite.config.mjs` returns matches

**INFRA-02 — Storage (local mode is fine for this verification):**

1. Start the backend with STORAGE_PROVIDER=local (default)
2. Upload a file via the manager dashboard (e.g., a delivery proof or any file attachment)
3. Verify the file appears in .rotas_uploads/ on disk
4. Run the migration script dry-check (no R2 needed for this):
   ```bash
   cd backend && python scripts/migrate_files_to_r2.py --help 2>&1 || echo "Script exists"
   python -c "import ast; ast.parse(open('scripts/migrate_files_to_r2.py').read()); print('Syntax OK')"
   ```
5. Confirm ExportJob.file_id column exists in DB:
   ```bash
   cd backend && alembic current
   ```
   Should show the add_export_job_file_id migration as head

**INFRA-03 — Tenant Limits:**

1. Start the backend and manager app
2. Check the limits endpoint:
   ```bash
   curl -H "Authorization: Bearer <your-token>" http://localhost:8000/api/v1/tenant/limits
   ```
   Expected shape: { vehicles: { used, max, pct }, drivers: ..., users: ..., upgrade_url }
3. If your test tenant has max_vehicles=5 and currently has <5 vehicles, create vehicles until you hit the limit
4. On the 6th create attempt, verify HTTP 403 with body: { "error": "plan_limit_reached", "details": { "upgrade_url": ... } }
5. Open the manager dashboard in browser — verify the LimitWarningBanner does or does NOT appear based on current usage:
   - If any dimension >= 80% of limit: amber banner visible at top of all pages
   - If all dimensions < 80%: no banner
   - Banner should NOT have a dismiss (X) button

For the null/unlimited test (optional): temporarily set a tenant's max_vehicles to NULL in DB and verify no 403 on vehicle creation past the old limit.
  </how-to-verify>
