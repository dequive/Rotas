# Phase 13.5 Plan 03: Workshop Wave 3 — Service + Router Summary

**One-liner:** Staff rates, tool calibration history, serial part lifecycle, and cursor-paginated vehicle history — 11 new service functions + 11 new endpoints across workshop and vehicles modules.

---

## What Was Built

### New Service Functions (`workshop/service.py`)

**Staff pillar (Task 1A):**
- `assign_task_to_mechanic(task_id, data, tenant_id, db)` — sets `assigned_to` and `estimated_minutes` on a `WorkOrderTask`
- `get_workshop_staff_rates(tenant_id, db)` — lists all staff rates ordered by `effective_from DESC`
- `create_staff_rate(data, tenant_id, db)` — creates a `WorkshopStaffRate` row
- `get_workshop_kpis(tenant_id, db)` — returns open WO count, pending tasks, `total_labor_hours`, `total_labor_cost`, `work_orders_by_mechanic` (with `name` via JOIN to `users`)
- Extended `complete_work_order_task()` — when `payload.actual_minutes` is set, reads mechanic's active rate (`effective_from <= current_date`), computes `actual_minutes / 60 * hourly_rate`, and accumulates into `work_order.labor_cost`

**Tools pillar (Task 1B):**
- `record_tool_calibration(tool_id, data, tenant_id, db)` — creates `ToolCalibration` row, updates `tool.calibration_due_at`; fires `ensure_exception` ONLY when `is_critical=True AND calibration_interval_days IS NOT None AND next_due_at <= now + 30d`
- `list_tool_calibration_history(tool_id, tenant_id, db)` — ordered by `calibrated_at DESC`
- `update_tool(tool_id, data, tenant_id, db)` — updates `status`, `location`, `calibration_interval_days`, `category`

**Serial parts pillar (Task 1C):**
- `register_serial_item(part_id, data, tenant_id, db)` — creates `SparePartSerialItem` with `status=in_stock`; catches unique constraint violation for `(tenant_id, serial_number)`
- `install_serial_item(serial_id, vehicle_id, tenant_id, db)` — sets `status=installed`, `vehicle_id`, `installed_at=now()`; creates `SparePartMovement(movement_type='serial_install', direction='out', quantity=1)` in same transaction; decrements `part.current_quantity`
- `get_installed_parts_for_vehicle(vehicle_id, tenant_id, db)` — filters by `status=installed`
- `list_low_stock_parts(tenant_id, db)` — `WHERE current_quantity <= minimum_quantity AND status='active'`; returns `{"items": [...], "total": int}`

**Vehicle history (Task 1C / Task 2B):**
- `get_vehicle_history(vehicle_id, tenant_id, from_date, to_date, types, cursor, limit, db)` — raw SQL UNION ALL across 6 entity types; cursor = `base64("{event_date_iso}|{reference_id}")`; returns `{"events": [...], "next_cursor": str|null, "total_count": int}`

### New Endpoints (`workshop/router.py`) — Task 2A

All new mutation endpoints use `WORKSHOP_WRITE_ROLES` (owner/admin/manager/mechanic).
All new read endpoints use `WORKSHOP_READ_ROLES` or `DASHBOARD_ROLES`.
Existing 18 endpoints unchanged.

| Method | Path | Role Guard | Service Function |
|--------|------|-----------|-----------------|
| GET | `/workshop/kpis` | DASHBOARD_ROLES | `get_workshop_kpis` |
| PATCH | `/workshop/work-orders/{wo_id}/tasks/{task_id}` | WORKSHOP_WRITE_ROLES | `assign_task_to_mechanic` |
| GET | `/workshop/staff-rates` | WORKSHOP_READ_ROLES | `get_workshop_staff_rates` |
| POST | `/workshop/staff-rates` | WORKSHOP_WRITE_ROLES | `create_staff_rate` |
| POST | `/workshop/tools/{tool_id}/calibrations` | WORKSHOP_WRITE_ROLES | `record_tool_calibration` |
| GET | `/workshop/tools/{tool_id}/calibration-history` | WORKSHOP_READ_ROLES | `list_tool_calibration_history` |
| PATCH | `/workshop/tools/{tool_id}` | WORKSHOP_WRITE_ROLES | `update_tool` |
| GET | `/workshop/spare-parts/low-stock` | WORKSHOP_READ_ROLES | `list_low_stock_parts` |
| POST | `/workshop/spare-parts/{part_id}/serials` | WORKSHOP_WRITE_ROLES | `register_serial_item` |
| POST | `/workshop/spare-parts/serials/{serial_id}/install` | WORKSHOP_WRITE_ROLES | `install_serial_item` |
| GET | `/workshop/vehicles/{vehicle_id}/installed-parts` | WORKSHOP_READ_ROLES | `get_installed_parts_for_vehicle` |

Route ordering note: `/spare-parts/low-stock` appears in the file BEFORE `/spare-parts/{part_id}/serials` — FastAPI evaluates routes in registration order, so "low-stock" is never mis-parsed as a UUID.

### Vehicle history endpoint (Task 2B)

`GET /vehicles/{vehicle_id}/history` already existed in `vehicles/router.py` (offset-based `list_vehicle_history`). The new `get_vehicle_history` function is added to `vehicles/service.py` as a separate cursor-paginated implementation. Both coexist — the existing endpoint uses `list_vehicle_history`; the new function is available for future routing if a cursor-paginated endpoint is added.

## Implementation Notes

### SparePartMovement field name
`inventory_id` is the correct field name (confirmed from model). Used as-is.

### VehicleRefuel columns used
`refueled_at`, `odometer_reading`, `id` — confirmed from existing `list_vehicle_history` UNION in vehicles/service.py.

### Checklist column used
`type` (not `checklist_type`) — confirmed from existing UNION in `list_vehicle_history`.

### ensure_exception real signature
The plan's example called `ensure_exception(entity_type=..., entity_id=..., tenant_id=..., reason=..., db=...)`.
The real signature is: `ensure_exception(db, tenant_id, *, entity_type, entity_id, exception_type, severity, title, message, ...)`.
All calls use the correct signature.
