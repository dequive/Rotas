## Decisions Made

- **Hover via inline style handlers, not Tailwind hover:** Tailwind's `hover:` pseudo-classes work well for static color values but CSS variable values (`var(--sidebar-hover)`) can't be directly used as Tailwind class arguments. The `onMouseEnter`/`onMouseLeave` approach is explicit and debuggable.
- **`border-l-2 border-transparent` for inactive items:** Keeps left padding identical between active (`border-amber`) and inactive states, preventing a 2px layout shift when active item changes.
- **`settings` entry is a placeholder:** The `/settings` page doesn't exist yet. The nav entry is present per DESIGN.md structure spec. The link renders but leads to a 404 until the page is built.
- **Inline `style` props for sidebar-specific tokens:** The sidebar background (`#0f1623`) uses a raw hex defined in the CSS variable `--sidebar-bg`. Using `style={{ background: "var(--sidebar-bg)" }}` is more readable than `className="bg-sidebar-bg"` and avoids potential Tailwind purge edge cases on dark hex values.
