FIRST: Read `backend/tests/conftest.py` to understand available fixtures (tenant, driver, vehicle, trip factories, db session, client). Read one existing test file (e.g., `backend/tests/test_trips.py`) to understand how trips are created in tests.

Then write `backend/tests/test_hos_service.py` with these named tests:

**test_hos_calculation_correct:**
- Create a tenant, driver, vehicle
- Create 2 completed trips for that driver today: one with actual_departure=now-3h, actual_arrival=now-1h (2h) and one with actual_departure=now-5h, actual_arrival=now-4h (1h)
- Call `calculate_driving_hours(driver.id, tenant.id, db)`
- Assert `hours_today == 3.0` (2h + 1h) and `status == "ok"`

**test_hos_violation_blocks_trip:**
- Create driver with 9.5h driven today (one trip: actual_departure=10h ago, actual_arrival=0.5h ago, status="completed")
- Call `create_trip()` with that driver assigned (or POST to /api/v1/trips)
- Assert response is 409 with `error_code == "hos_violation_active"` and `details.override_required == True`

**test_hos_override_allows_trip:**
- Same setup as above (driver with 9.5h today)
- Call create_trip with `hos_override_reason="Emergency delivery — approved by operations manager"`
- Assert trip is created successfully (201)

**test_hos_tenant_isolation:**
- Create two tenants, two drivers (one per tenant)
- Add a 9.5h trip to driver in tenant A
- Call `calculate_driving_hours(driver_b.id, tenant_b.id, db)` — driver B in tenant B
- Assert `hours_today == 0.0` — tenant A trips are NOT counted for tenant B driver

**test_hos_week_calculation:**
- Create driver with trips spanning Mon-Fri of current week, totaling 50h (e.g., 10h per day for 5 days)
- Call `calculate_driving_hours()` with target_date=Friday
- Assert `hours_this_week >= 48.0` and `status == "violation"` and `violation_reason == "weekly_limit"`

Use `pytest.mark.asyncio` and the existing async session fixture. If the conftest does not have a `trip_factory`, create trips directly using SQLAlchemy ORM: `Trip(tenant_id=..., driver_id=..., vehicle_id=..., status="completed", actual_departure=..., actual_arrival=..., origin="X", destination="Y")`.

Use `datetime.now(UTC) - timedelta(hours=N)` for departure/arrival times.

Write `backend/tests/test_availability_endpoints.py` with these named tests:

**test_availability_drivers_endpoint:**
- Create tenant with 2 active drivers and 1 inactive driver
- GET /api/v1/availability/drivers (authenticated as manager user for that tenant)
- Assert response is 200
- Assert response has `total` and `items` keys
- Assert `len(items) == 2` (only active drivers)
- Assert each item has `driver_id`, `driver_name`, `available`, `blockers`, `hos_status` keys

**test_availability_vehicles_endpoint:**
- Create tenant with 2 active vehicles
- Create an active WorkOrder (status="in_progress") for one vehicle
- GET /api/v1/availability/vehicles
- Assert response is 200
- Assert one vehicle has `computed_status == "in_maintenance"`
- Assert the other vehicle has `computed_status == "available"`

**test_availability_status_filter:**
- Create tenant with 1 available driver and 1 driver with HOS violation (9.5h driven today)
- GET /api/v1/availability/drivers?status=available
- Assert only 1 driver returned
- GET /api/v1/availability/drivers?status=hos_violation
- Assert only 1 driver returned (the one in violation)

**test_vehicle_maintenance_blocks_trip (integration):**
- Create tenant, vehicle, driver
- Create active WorkOrder for the vehicle (status="in_progress")
- POST /api/v1/trips with that vehicle assigned
- Assert 409 response with `error_code == "vehicle_workshop_blocked"`
- Assert response includes `work_order_id` in details

This last test validates that `require_vehicle_available()` correctly blocks assignment — it already works from the existing service, but we verify it end-to-end via HTTP.

Use `AsyncClient` with `base_url` from existing test patterns. All requests need a valid JWT for a manager user — use the `auth_headers` or equivalent fixture from conftest.
