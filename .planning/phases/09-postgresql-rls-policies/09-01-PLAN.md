  <action>
    The current `startup()` function sets `ctx["db_factory"] = AsyncSessionLocal` which is bound to `database_url` (the `rotas_app` role, subject to RLS). Once RLS is active, cross-tenant ARQ jobs — such as `generate_billing_export` which queries `ExportJob` rows across tenants — will be silently blocked or return empty results with no error.

    Fix: create a separate async engine and session factory in `startup()` using `settings.resolved_admin_database_url`.

    Replace the `startup` function body:
    ```python
    async def startup(ctx: dict) -> None:
        from sqlalchemy.ext.asyncio import async_sessionmaker, create_async_engine
        from app.config import get_settings as _get_settings

        _settings = _get_settings()
        # D-18 / RLS-02: ARQ worker uses rotas_admin role (BYPASSRLS) for cross-tenant queries.
        # resolved_admin_database_url falls back to database_url in local dev where RLS may not
        # be active — no local dev config change required.
        admin_engine = create_async_engine(
            _settings.resolved_admin_database_url,
            pool_pre_ping=True,
        )
        ctx["db_factory"] = async_sessionmaker(admin_engine, expire_on_commit=False)
        ctx["admin_engine"] = admin_engine  # store for cleanup in shutdown
    ```

    Also update `shutdown()` to dispose the engine:
    ```python
    async def shutdown(ctx: dict) -> None:
        if "admin_engine" in ctx:
            await ctx["admin_engine"].dispose()
    ```

    No other changes. `WorkerSettings`, `generate_billing_export`, and the rest of the file stay identical.

    Note: `generate_billing_export` already includes `BillingDocument.tenant_id == UUID(tenant_id)` filters in its queries — it is written correctly for the admin role (explicit tenant filter even though BYPASSRLS). Do not remove these filters (per CLAUDE.md: "never remove tenant_id filter in optimizations").
