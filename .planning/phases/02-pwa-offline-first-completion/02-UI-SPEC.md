# Phase 2 — UI Design Contract

> Visual and interaction contract for the PWA Offline-First Completion phase.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This phase has one new UI deliverable: the `SyncStatusBanner` component that replaces
> the existing `.offline-bar` footer. All other driver PWA screens are unchanged.
> The manager Next.js app receives no visual changes in this phase (only token refresh logic).

## Spacing Scale

The existing codebase uses an informal 8-point scale with values 4, 6, 8, 10, 12, 14, 20, 24, 32.
Declared tokens for new components in this phase use only canonical 8-point values:

| Token | Value | Usage |
|-------|-------|-------|
| xs    | 4px   | Icon gaps, counter prefix spacing |
| sm    | 8px   | Inline gap between banner icon and text; banner vertical padding |
| md    | 16px  | Banner horizontal padding |
| lg    | 24px  | Section spacing (existing screens, not new in this phase) |
| xl    | 32px  | Not used in this phase |
| 2xl   | 48px  | Not used in this phase |
| 3xl   | 64px  | Not used in this phase |

Exceptions:
- Touch targets: minimum 44px height on all interactive elements (existing `.icon-btn` already at 44px). The "Verificar atualizações" button inside the banner must be min-height 32px as a secondary inline action.
- Banner height: fixed 48px min-height to prevent layout shift between banner states.

Banner padding: `padding: 8px 16px` — 8px vertical (`sm`) + 16px horizontal (`md`).

## Visual Focal Points

### Primary Driver Screen (Dashboard)

The dashboard header / trip status card is the primary focal element on the driver's main screen.
It occupies the top portion of the `.phone-shell` flex column and communicates the most critical
state: whether a trip is active, the current trip name, and elapsed distance/time counters.
All other cards below it (fuel, stops, checklist) are secondary content layers.

The primary focal hierarchy on the dashboard is:
1. Trip status card / header (`.top` section with `.top h1`) — Display 24px, weight 800
2. Action buttons (`.primary-action`) — accent blue, full-width, high contrast
3. Secondary cards/panels — white surface on `--soft` background

### SyncStatusBanner

The `SyncStatusBanner` is a secondary status layer mounted at the bottom of `.phone-shell`
(`margin-top: auto`). It is subordinate to the dashboard focal hierarchy — it provides ambient
status without competing for the driver's primary attention. When `idle`, it is hidden entirely.
When visible, its color-coded background (orange/green/red/blue) signals urgency without requiring
the driver to read the text first.

## Component Inventory

### SyncStatusBanner

Replaces the existing `.offline-bar` footer element. The existing `.offline-bar` is removed
from `App.tsx` and replaced by `<SyncStatusBanner />` mounted at the same position (bottom of
`.phone-shell` flex column, `margin-top: auto`).

**States:**

| State | Trigger | Visible? | Content |
|-------|---------|----------|---------|
| `idle` | Online, queue empty, no update pending | Hidden (display: none) | — |
| `offline` | `navigator.onLine === false` | Always visible | "Sem ligação — a gravar localmente · X registos pendentes" |
| `syncing` | Online + sync in progress | Visible until sync completes | "A sincronizar... · X registos pendentes" |
| `error` | Items exceed Workbox retry limit | Visible until cleared | "X registos com erro — contacta o gestor" |
| `session_expired` | Refresh token TTL expired (30 days) | Visible until re-paired | "Sessão expirada — contacta o teu gestor para re-parear o dispositivo" |
| `access_revoked` | Backend returns `driver_access_revoked` | Visible, non-dismissible | "Acesso revogado. Os teus registos locais foram preservados — contacta o teu gestor." |
| `update_available` | SW `waiting` worker detected | Visible until tapped | "Nova versão disponível" + "Verificar atualizações" button |

**Structure:**

```
.sync-banner  (base class, always mounted)
  └── .sync-banner__message   (status text + counter)
  └── .sync-banner__action    (optional: "Verificar atualizações" button — only in update_available state)
```

**Layout:** `display: flex; justify-content: space-between; align-items: center; padding: 8px 16px; min-height: 48px;`

**Transition:** `background-color 0.2s ease, color 0.2s ease` — smooth color cross-fade between states.
No slide animation. The banner occupies fixed space at the bottom of the shell; it does not
push content when it appears (always mounted, only visually hidden when `idle`).

**Counter source:** `db.syncQueue.where('status').anyOf(['local_only', 'retrying']).count()`
Counter refreshes every 5 seconds when banner is visible.

**"Verificar atualizações" button:** appears only in `update_available` state. On tap, calls
`registration.waiting.postMessage({ type: 'SKIP_WAITING' })` then `window.location.reload()`.
Style: `.small-btn` with `--blue` colors (matches existing `.small-btn` class).

### useNetworkStatus hook

New hook in `apps/driver/src/hooks/useNetworkStatus.ts`.
Returns `{ isOnline: boolean }` using `navigator.onLine` + `window.addEventListener('online' | 'offline')`.

### useSyncStatus hook

New hook in `apps/driver/src/hooks/useSyncStatus.ts`.
Aggregates: `isOnline`, `isSyncing`, `pendingCount`, `errorCount`, `sessionState` (`'ok' | 'expired' | 'revoked'`), `updateAvailable`.
Drives `SyncStatusBanner` state machine.

## Interaction Contract

### SyncStatusBanner state machine

```
idle ──(go offline)──────────────────────────► offline
offline ──(come online)──────────────────────► syncing
syncing ──(sync success + queue empty)────────► idle
syncing ──(sync partial failure)──────────────► error
error ──(user re-opens app + queue drains)────► idle
any ──(refresh token expires)─────────────────► session_expired
any ──(backend returns driver_access_revoked)─► access_revoked
any ──(SW waiting worker detected)────────────► update_available (overlaid on current state)
```

`update_available` is shown as a secondary layer — it does not replace `offline` or `error`.
When both `offline` and `update_available` are true, show `offline` (primary) with the
"Verificar atualizações" button appended. Network stability is more actionable than an update.

### Token refresh (AUTH-02 driver PWA)

Silent — no UI. Driver never sees a loading state or prompt during refresh. The refresh happens
in `api.ts` before any sync batch submission, using an in-memory lock to prevent parallel races.
If refresh fails because the refresh token has expired (30-day TTL), the app transitions the
`SyncStatusBanner` to `session_expired` state. No modal. No forced logout. App remains fully
functional offline — only sync is blocked.

### Access revocation (D-08)

When backend returns `{"error": "driver_access_revoked"}` on sync, the app:
1. Does NOT clear Dexie data
2. Does NOT log the driver out
3. Transitions `SyncStatusBanner` to `access_revoked` state
4. Freezes all future sync attempts until re-paired

### Token refresh (AUTH-01 manager Next.js)

No new manager UI. Refresh is handled in the server action layer (`apps/manager/app/lib/auth.ts`).
No loading indicator, no error state visible to manager users in this phase.
