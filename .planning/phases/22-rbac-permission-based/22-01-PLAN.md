    - Principal(role="mechanic").has_any_permission(frozenset({"workshop.write"})) returns True
    - Principal(role="mechanic").has_any_permission(frozenset({"billing.read"})) returns False
    - Principal(role="admin", permissions=frozenset({"billing.read"})).has_any_permission(frozenset({"billing.write"})) returns False (explicit permissions override role lookup)
    - create_access_token(permissions=frozenset({"billing.read"})) produces JWT with "perms": ["billing.read"]
    - create_access_token(permissions=None) produces JWT WITHOUT "perms" key (not "perms": null)
    - get_current_principal() with a JWT containing "perms": ["fleet.read"] returns Principal with permissions=frozenset({"fleet.read"})
    - get_current_principal() with a JWT lacking "perms" returns Principal with permissions=None
  </behavior>
  <action>
    PART A — auth.py modifications:

    1. Add to Principal dataclass (after device_id, before any method):
       permissions: frozenset[str] | None = None

    2. Add has_any_permission method to Principal:
       def has_any_permission(self, required: frozenset[str]) -> bool:
           from app.core.rbac import ROLE_PERMISSIONS  # late import — breaks circular dep
           effective = (
               self.permissions
               if self.permissions is not None
               else ROLE_PERMISSIONS.get(self.role or "", frozenset())
           )
           return bool(effective & required)

    3. In get_current_principal(), AFTER the JWT claims are decoded and validated (after the
       driver_app branch), extract the perms claim:
       raw_perms = claims.get("perms")  # list[str] | None
       permissions = frozenset(raw_perms) if raw_perms else None

    4. Update the return Principal(...) at bottom of get_current_principal() to add:
       permissions=permissions,

    5. The dev-test-token Principal(...) return does NOT need permissions= — it stays as-is.
       None triggers the ROLE_PERMISSIONS["admin"] fallback in has_any_permission(), which is
       the correct behavior (dev token has admin permissions via fallback).

    PART B — tokens.py modifications:

    1. Add permissions: frozenset[str] | None = None parameter to create_access_token().

    2. In the claims dict, conditionally add the perms key:
       if permissions is not None:
           claims["perms"] = sorted(permissions)
       Do NOT set claims["perms"] = None — omit the key entirely when permissions is None.
       This keeps backward compat: existing token decoders that don't know about "perms"
       will simply ignore it; our decoder uses claims.get("perms") which returns None for absent.
  </action>
